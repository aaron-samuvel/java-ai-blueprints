java-ai-blueprints

Enterprise Java & Spring Boot AI systems, built as working code. A Maven multi-module project with one folder per topic: theory, runnable examples, exercises, a project and tests. Every module builds and tests offline with deterministic stub models; live tests against Ollama and pgvector are opt-in.

This page documents the apps; it is not a live demo. The blueprints are Java servers (Spring Boot) that need a JVM, and some need PostgreSQL/pgvector and Ollama, so they run on your own machine. The handbook-shaped packages added later (one per blueprint) are verified by the offline test suite on the build box and in CI. They were not part of that Windows run.

Part III · Blueprints

Blueprint 01 · port 8081

GOAP / OODA FinOps incident agent

Watches a cloud bill and runs an OODA loop (Observe, Orient, Decide, Act). Decide is a Goal-Oriented Action Planner searched with A*; the agent re-plans every cycle and runs only the first action, so new facts (a denied approval, an unknown cause) change course. The handbook's CloudRemediationAgent (@Agent, @Condition ≥ 0.80, deep-trace path, Spring Shell execute) runs on a small Embabel-style platform. 20 tests.

Run locally

mvn -B -pl blueprint-01-goap-finops-incident-agent -am spring-boot:run
curl -X POST http://localhost:8081/api/incidents/run \
  -H "Content-Type: text/csv" \
  --data-binary "@blueprint-01-goap-finops-incident-agent/src/main/resources/billing-sample.csv"

Real result

HTTP 200
{"outcome":"ESCALATED","service":"batch-etl","todayInr":6400.00,"baselineInr":803.33,"cause":"UNKNOWN", …}

Recorded with PORT=18081 because 8081 was busy on the test PC; the default is 8081.

Blueprint 02 · port 8082

LangGraph4j human-in-the-loop evaluation

A LangGraph4j state graph: a drafter agent writes, an evaluator agent gates it with Spring AI evaluators, then the graph pauses for a human. The paused state is checkpointed so a reviewer can approve or reject over REST; a rejection sends the draft back with the comment. The handbook's submission graph adds 4 parallel evaluators, reducer channels, a consensus node with 3 exits and a JDBC checkpoint saver. 25 tests.

Run locally

mvn -pl blueprint-02-langgraph4j-hitl-evaluation -am spring-boot:run
# POST http://localhost:8082/api/reviews, then approve the review

Real result

  • POST /api/reviews → AWAITING_HUMAN
  • approve → PUBLISHED
  • history shows 3 draft/review rounds

Blueprint 03 · port 8083

Modular, branching, conditional RAG

Built from Spring AI's modular RAG parts: a router sends each question down a branch, a domain-filtered retriever searches only the matching corpus, and a conditional augmenter makes the model decline when nothing relevant is found. Production storage is pgvector; includes a measured TOON-vs-JSON token comparison. The handbook's pipeline adds Tika/PDFBox ingestion that is idempotent by hash, multi-query, branching retrieval and cited answers. 35 tests.

Blueprint 04 · port 8084

Transactional agent swarm, tenant-partitioned memory

Triage, refund and notify agents share one conversation memory and run inside one @Transactional boundary. If any agent or rule fails, the refund row, the outbox message and the chat memory roll back together. Memory is stored per tenant in the same database. The handbook's commerce swarm adds triage, product, order and refund agents with handoffs, SSE and a live swarm.html badge page. 21 tests.

Run locally

mvn -pl blueprint-04-transactional-swarm -am spring-boot:run

Blueprint 05 · port 8085

Zero-trust PII tokenisation advisor

Raw personal data never reaches the model. A Spring AI CallAdvisor replaces PII (email, PAN, card, Aadhaar, Indian phone) with opaque tokens like <<EMAIL_1>>, then swaps real values back before the answer reaches the user. Tool outputs are governed per method by @ToolPrivacyPolicy. The handbook's guardrails package adds a regex + OpenNLP + Presidio analyzer SPI, a request-scoped vault, response policies, least-privilege tools and a privacy-boundary inspector. 32 tests.

Run locally

mvn -pl blueprint-05-pii-tokenization-advisor -am spring-boot:run   # stub model
BLUEPRINTS_MODEL=ollama mvn -Pit -pl blueprint-05-pii-tokenization-advisor -am spring-boot:run

Real result (stub model)

POST /api/chat → HTTP 200

The values above are the module's built-in sample test data, not real personal data. The stub echoes the restored text.

Blueprint 06 · port 8086

MCP server mesh and model switchboard (OAuth2)

A Spring AI MCP server (Streamable HTTP at /mcp), a mesh client that merges tools from N nodes, an OAuth2 resource server, and a switchboard that routes CHAT → LOCAL_FAST, ANALYSIS → LOCAL_SMART, CRITICAL → PREMIUM, downgrading when the models.premium scope is missing. The handbook's ops node adds Spring Batch introspection with guarded restart, JFR diagnostics and a dynamic OpenAPI-to-MCP bridge. The v2 router adds a timeout fallback and StructuredOutputValidationAdvisor. 22 tests.

Run locally

# set BLUEPRINTS_DEV_JWT_SECRET to a random value of 32+ bytes first
mvn -B -pl blueprint-06-mcp-mesh-model-switchboard -am spring-boot:run
# second shell, same secret: mint a local dev token (after mvn -q -am install -DskipTests)
TOKEN=$(mvn -q -pl blueprint-06-mcp-mesh-model-switchboard exec:java \
  -Dexec.mainClass=io.github.aaronsamuvel.blueprints.mcp.security.DevJwtMinter \
  -Dexec.args="models.use models.premium")
curl -X POST http://localhost:8086/api/switchboard/ask \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"task":"CRITICAL","message":"hi"}'

Real result

  • No token → 401
  • Basic access, CRITICAL → LOCAL_SMART (downgraded)
  • Premium scope, CRITICAL → PREMIUM
  • CHAT → LOCAL_FAST
  • /mcp without tool scope → 403; with scope, tools: listServices, monthToDateCost

Blueprint 07 · port 8087

A2A agent + self-healing NL2SQL

Turns questions into SQL and can be called by other agents. Every query passes a JSqlParser guard: one read-only SELECT, allow-listed tables, LIMIT 500 enforced. Rejected SQL is fed back to the model for up to 3 self-healing retries (4 calls max). Runs on H2 offline. The handbook's DataAgent adds a schema vector index, tenant-injecting AST guardrails, EXPLAIN-checked self-healing, chart specs, an A2A JSON-RPC message/send mesh and Sequential/Parallel/Loop agents. 36 tests.

Run locally

mvn -pl blueprint-07-a2a-nl2sql-agent -am spring-boot:run   # H2, stub model
curl http://localhost:8087/.well-known/agent.json

Real result

  • GET /.well-known/agent.json → 200
  • NL2SQL task with the stub model → FAILED after 4 attempts (SQL does not parse), exactly as the README describes: the stub cannot write SQL, so this shows the guard and retry loop working. Use a real model for answers.

Part IV · Pillars

pillar-finops-budget · library + demo

FinOps reserve-call-commit budget advisor

A Spring AI CallAdvisor that gives each tenant a token budget and enforces it with reserve → call → commit. Over-budget calls are blocked before the model is called, concurrent calls can't overspend, and failed calls release their reservation. A JDBC ledger with daily budgets reserves with one atomic conditional UPDATE: 32 concurrent reservations against 10 slots grant exactly 10.

Run locally

mvn -q -pl pillar-finops-budget -am install -DskipTests
mvn -q -pl pillar-finops-budget exec:java \
  -Dexec.mainClass=io.github.aaronsamuvel.blueprints.finops.FinOpsDemo

pillar-eval-gates · library

JUnit evaluation gates

JUnit tests that fail the build when AI answers stop being relevant or grounded, using Spring AI's RelevancyEvaluator and FactCheckingEvaluator over a golden set. The judge is pluggable: a deterministic lexical judge offline, or Ollama llama3.2:3b live. Five gates: groundedness and relevance (handbook), plus structured output, PII leak and answer token budget (author's design). json-io TOON measured: 32% fewer tokens on flat tables, 1.8% more on nested objects.

Run locally

mvn -B -pl pillar-eval-gates -am verify        # offline judge
mvn -B -Pit -pl pillar-eval-gates -am verify   # live Ollama judge

Real result

  • 19 tests pass
  • Live judge (llama3.2:3b): golden relevancy 80%, facts 100%
  • All 3 deliberate regressions caught
